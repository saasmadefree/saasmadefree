# Design context — SaaS Made Free

## Design Context

### Users

Two audiences with opposite tolerances share every page.

**The sceptic.** Developers and technical operators who pay for SaaS subscriptions and
want to know which of them they could rebuild with a coding agent. They verify before they
believe: they will read `extension/content.js` before trusting a privacy claim, and
rebuild the extension and compare the SHA-256 before trusting a download. They arrive half
expecting an affiliate site in disguise, and they are looking for the tell.

**The searcher.** A larger, less technical and less patient audience arriving from search
for one specific tool. One question, no interest in the project's ethics. They need the
verdict and the real price above the fold, with nothing between them and it.

The job, for both: decide whether a subscription can be dropped, learn what is actually
lost by dropping it, and leave with a prompt that works — while being able to check that
this is not quietly an affiliate site.

### Brand Personality

**Honest to the point of being unhelpful to itself.** The name promises free; the
catalogue immediately qualifies the promise. Only a minority of entries are a clean
`yes`, and a large minority say *keep paying* outright. The product says so before it says
anything else — that is the entire differentiator, and the reason this reads as a
directory rather than an affiliate site.

Three words: **documentary, verifiable, unsold.**

The register is a document, not a pitch. Verdicts, sources, dates. No urgency, no
exclamation, no growth-marketing voice. If a sentence could appear on a landing page
selling a course, it is wrong for this project.

**Never hardcode an aggregate figure into prose — this file included.** Run `npm run
stats`; it reads `data/tools/` live. A percentage copied by hand drifts the moment the
next import lands, and this project's whole argument is that its numbers are true. This
document asserted a verdict distribution that was wrong by twenty points for exactly that
reason, while `README.md` — which refuses to name a figure and points at the command
instead — stayed correct. Follow the README's habit.

### Aesthetic Direction

**« Le Dossier instruit »** — chosen 2026-08-04, specified in
`docs/superpowers/specs/2026-08-04-refonte-dossier-design.md` (that spec is the source of
truth for every value; this section is the summary). The site is an instructed
administrative file: each tool is a numbered dossier, each page a piece of evidence
annotated by a controller — kraft folders with tabs, ivory sheets, stamps, marginal
annotations in pen, checked boxes, cross-references. Deliberately maximalist — the
minimalist directions were explored and rejected — under one law: **every visual artifact
carries a fact computed from the data.** A stamp without a date, an annotation without a
source, a number without a real order are forbidden.

Three system font families, three roles: monospace (the machine — body, values, prompt),
condensed sans (the printed form — labels, stamps, tabs), Georgia italic (the
controller's hand — annotations). No webfont, by choice.

Closed palette: papers (kraft desk, folder, ivory sheets), neutral inks (brown-black),
and the active inks — controller's pen `#2d3a52`, pale highlighter (background only), and
the three verdict stamp inks (green `#2f5d33`, amber `#6b4600`, red `#9c2a1c`) plus the
round date stamp `#28522c`. **Verdict inks serve only the verdict.** Dark theme is kept,
as dusk paper — bistre grounds, lightened stamp inks, AA maintained.

Still avoided, unchanged: glowing accents, gradient text, decorative gradients,
glassmorphism, animations (the printed world does not move), and any figure typed by hand.

The browser extension is the deliberate exception and the opposite: dark, compact, sitting
on top of someone else's page, where it must never be mistaken for the host site.

### Design Principles

1. **The verdict is the only colour.** Everything else is paper, ink and rule. A second
   saturated hue anywhere in the interface devalues the one piece of information the page
   exists to deliver.
2. **Colour never carries meaning alone.** The verdict label ships with the badge, always.
   A reader with deuteranopia, or with colour stripped by a reader mode, loses nothing.
3. **Every number is read from the data at build time.** Figures, counts, prices and
   percentages are computed, never typed. A number that cannot be computed is not shown.
4. **Nothing is fetched from a third party.** No CDN font, no analytics, no embed, no
   tracking pixel. The privacy claim is verifiable by reading the page source, and that is
   the point.
5. **The page works before the JavaScript does.** Categories are real indexable pages and
   real links, not client-side filters. Search and filtering are enhancements layered on a
   page that is already complete without them.

## Accessibility

Target: **WCAG 2.2 AA.** Text contrast at least 4.5:1 (3:1 for large text and for UI
boundaries) in both themes, visible focus on every interactive element, full keyboard
navigation, and no interaction that depends on hover or pointer alone.

On top of AA, the colour-blind guarantee of principle 2 is a hard requirement rather than a
recommendation: green / amber / red must never be the sole carrier of the verdict.

`prefers-reduced-motion` must disable the home-page ticker and every entrance animation.
`prefers-color-scheme` selects the theme, and an explicit reader choice
(`:root[data-theme]`) overrides it.

## Constraints

Static site, generated by plain Node ESM into `dist/` (`scripts/build-site.mjs` and
`scripts/lib/site-*.mjs`) — no framework, no runtime dependency, no build step for the
served pages. One stylesheet, emitted once, from `scripts/lib/site-styles.mjs`. Served by
Cloudflare Pages. No external request of any kind.

Surfaces and languages:

- **UI strings** exist in seven locales (`data/i18n/`: de, en, es, fr, it, nl, pt), and
  `npm run validate` enforces that all seven stay complete.
- **The public site** publishes only the languages actually present in the tools'
  `markets` — today `en` and `fr`. The list is derived at build time by `siteLanguages()`,
  so the site gains a language on its own the day the tool data carries one; nothing is
  hardcoded.
- **The extension** ships all seven.

Any layout must therefore hold under text expansion (German and Dutch run long) and must
never assume the language count is two.
