Une base de données façon tableur mono-utilisateur — colonnes typées, vues enregistrées, enregistrements liés — se construit en une session au-dessus d’une vraie base de données. Ce qui ne vient pas avec, c’est l’étendue d’Airtable : des dizaines de types de champs, des automatisations, une API générée, des applications mobiles, et des permissions de partage fines pour une équipe.

Le prompt Copier Claude Code Cursor

Construis une base de données façon tableur personnelle : une interface en grille au-dessus d’une vraie base de données (SQLite convient), où les tables et les colonnes typées (texte, nombre, date, sélection unique, case à cocher, URL) se définissent depuis l’interface, pas depuis un fichier de config. Prends en charge l’édition de cellule en ligne, le tri et le filtre par colonne, et des vues enregistrées — un nom plus une combinaison filtre/tri/colonnes masquées mémorisée — listées dans une barre latérale. Ajoute un type de colonne « enregistrement lié » : une cellule qui référence une ligne d’une autre table, choisie dans un menu déroulant, affichée comme une puce cliquable.

Ne construis pas d’automatisations, d’API générée, ni de permissions par personne — ce sont les éléments qui transforment une base de données personnelle en plateforme d’équipe, et c’est vraiment plus qu’une session de travail.
