## Blocking defects

1. **dropbox-plus · 1 · `alternativesIntro`**: "keep paying $9.99 a month". `data/tools/dropbox-plus.json` pricing is **€9.99 (EUR)**,
   read from the EU page, and its note says upstream recorded $11.99. The text shows the wrong currency.
   Fix: write "€9.99 a month", or source a USD figure from dropbox.com/plans and update the data.
2. **dropbox-plus · 1 (honesty) · `alternativeNotes.syncthing` and `faq[5].a`**: "It has no web interface". This is false.
   Syncthing ships a web admin GUI, and our own Syncthing page says so ("a web admin interface", port 8384).
   Fix: "It has no web file browser, no sharing links and no cloud storage".
3. **shopify · 3 · `alternativesIntro`, `faq[4]`, `alternatives` order**: Bagisto as "best free Shopify alternative" does not hold up.
   Our own Bagisto page says it needs PHP 8.4 and Laravel 13, that theming and extensions "usually call for a PHP developer",
   and that B2B and marketplace features are separate products. Its theme and extension ecosystem is small. The intro's own list
   of what you lose (app marketplace, payments, shipping, tax) is exactly what WooCommerce covers best among these projects.
   Better choice: **WooCommerce**. It has the largest extension and theme catalogue (the nearest thing to Shopify's App Store),
   named payment gateways (WooPayments), runs on any cheap managed WordPress host, and a non-developer can run it. That fits
   the reader who is leaving Shopify. Second choice: PrestaShop or Shopware as standalone stores.
   Fix: move `woocommerce` to `alternatives[0]`, add an `"alternatives order"` source line, and rewrite the intro and FAQ 5 around it.
   Keep Bagisto as the pick for Laravel developers.
4. **shopify · 5 · `faq[5].a`**: "For Bagisto, Spree, WooCommerce, PrestaShop and Shopware, a technical owner can manage the install".
   This contradicts our project pages. Spree: "It is a developer platform: changing a storefront means writing code". Bagisto: theming
   "usually calls for a PHP developer". Shopware: "Needs PHP skills for installation, upgrades and plugins". Fix: put Spree with
   Medusa, Saleor and Solidus (developer-only), and say that Bagisto and Shopware need a PHP developer for themes and plugins.
5. **mailchimp · 1 (honesty) · `alternativesIntro`**: "[Listmonk] has no drag-and-drop editor". This is false. listmonk.app says:
   "Write HTML e-mails using a visual drag-and-drop builder, a WYSIWYG editor, Markdown…". Fix: drop that clause and keep
   "no visual automations and no e-commerce sync". Add the visual builder to `data/i18n/en/projects/listmonk.json` strengths, with a source line.
6. **mailchimp · 1 (honesty) · `alternativeNotes.keila`, `.sendportal`, `.phplist`**: "fewer automations", "limited automations"
   and "few automations" suggest these tools have some automation. Our own project pages say they have none. Keila: "No automation or
   drip-sequence builder: … only as a feature request (#132)". SendPortal: "lists no visual automation or drip-sequence builder, only campaigns".
   phpList: "no visual automation builder". Fix: "It has no automation builder". Also drop phpList's "dated interface", which has no source.
7. **opencloud · 1/2 · `description` and `limits[3]`**: dates in prose: "created in January 2025" and "Young project, created in 2025".
   Both the write-project brief and grid 1 ban dates, because the page shows live repo dates. Fix: delete the date sentence and replace
   the limit with a sourced, specific gap, e.g. "The main repository has no install guide for production; you rely on docs.opencloud.eu".
8. **wraft · 1/2 · `limits[3]`**: "a codebase that dates from September 2024" is a date in prose. "The project is young and small" in
   `description` is an unsourced opinion. Fix: remove both.
9. **medusa · 4 · `description` sentence 1**: "Medusa is a commerce platform with a built-in framework for customization." This is the

  write-project brief §5 allows them ("Licence and hosting facts come from data/projects"). The two briefs conflict, so I did

  "which our data prices from 75 USD". This is internal wording, and it is often wrong given the known `hosted` errors (Medusa, Bagisto,
  Wraft, OpenSign have hosted offers). Say what the vendor offers, with a source, or say nothing.

  open-core model"). Prefer "Open-core commerce framework" or "MIT-licensed core".

  ("can also be encrypted with a user chosen password"). Rewrite while fixing the rest.
- **graphite · description**: "mixes layer-based compositing with a node graph" and the roadmap list follow the README closely. Borderline.
- **wraft · limits[2]**: "do not list an e-signature feature, so it may not replace a signing service". wraft.app says "built-in
  e-signature and approval workflows", and the DocuSign note ("signing steps") agrees with the site. Update the project limit and source it to wraft.app.
- **pydio-cells**: the Dropbox note (`alternativeNotes.pydio-cells`) says it "Covers file sharing and sync", but the project page says the README
  describes no sync clients. Pick one, with a source (Cells Sync client docs).

- **mailchimp · notes**: Notifuse's note ("It is a newer project") skips its visual automation canvas (its strongest point against
